pydoctor-cli is a command-line tool that scans Python projects for common dependency and security problems. It requires Python 3.10 or later and works with pip, Poetry, uv, and pdm. See the [changelog](/changelog) for the latest release.

## What it scans

pydoctor-cli runs six scanners, each focused on a different risk area:

<CardGroup cols="2">
  <Card title="Security" icon="shield-check" href="/scanners">
    Queries the OSV vulnerability database for known issues in your installed packages.
  </Card>
  <Card title="Dependencies" icon="puzzle-piece" href="/scanners">
    Finds version conflicts and missing dependencies using pip or direct metadata inspection.
  </Card>
  <Card title="Outdated packages" icon="arrow-up" href="/scanners">
    Lists installed packages with newer releases available, flagging major version gaps as warnings.
  </Card>
  <Card title="Unused packages" icon="trash" href="/scanners">
    Finds declared dependencies that nothing in your code, settings, or run files appears to use.
  </Card>
  <Card title="Environment health" icon="desktop" href="/scanners">
    Checks your Python version, virtual environment, and pip version against recommended baselines.
  </Card>
  <Card title="CI/CD checks" icon="lock" href="/scanners">
    Scans committed files for leaked secrets and workflow files for unpinned actions, script injection, and other risks.
  </Card>
</CardGroup>

## Health score

Every scan produces a health score on a 0 to 100 scale. The score starts at 100 and decreases based on the severity and category of each issue found. Each category has a cap on how many points it can cost, and extra issues within a category have diminishing returns. Any critical-severity issue caps the score at 69, preventing a Good or Excellent verdict. Five verdict bands summarize the result:

| Score | Verdict |
|---|---|
| 90 to 100 | Excellent |
| 70 to 89 | Good |
| 50 to 69 | Needs Attention |
| 0 to 49 | Critical |
| (any) | Incomplete |

The Incomplete verdict appears when part of the scan could not run, for example when the project environment could not be read. The score covers only the checks that completed.

You can set a minimum passing score in your `pyproject.toml` with the `min_health_score` option under `[tool.pydoctor]`. When the score falls below that threshold, the CLI exits with code 1, which makes it straightforward to use as a CI gate.

## Output formats

By default, results render as Rich terminal panels grouped by category, with a colored health-score bar and a next-steps guide. Pass `--json` to any scan command for machine-readable JSON output suitable for CI pipelines or further processing.
