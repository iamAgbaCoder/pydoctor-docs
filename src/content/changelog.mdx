## 2.2.0

Every change in this release removes a case where pydoctor reported a problem as fine, or got a severity wrong.

- **Scans the right environment.** Facts come from your project's interpreter, not pydoctor's. Under pipx or `uv tool`, and in uv environments (which have no pip), 2.1.0 saw 0 packages and reported everything as OK. Works without pip. New `--python` option and `PYDOCTOR_PYTHON`; the report shows which interpreter was scanned and why. See [Scanned environment](/scanners#scanned-environment).
- **Fails loudly.** `ENV_PACKAGES_UNAVAILABLE` (error) when the environment can't be read, `ENV_DEPS_NOT_INSTALLED` (warning) when the scanned Python has none of your dependencies, and `PKG_OUTDATED_UNAVAILABLE` when the outdated check can't run, instead of "all up to date".
- **Virtualenv detection works.** It always reported "active". The `diagnose` no-venv prompt now appears, and never blocks CI or piped runs.
- **Real CVSS severity.** Calculated from the CVSS v3 vector. Previously a 3.1 (Low) and a 9.8 (Critical) vulnerability were both shown as critical. GitHub's `MODERATE` is now medium.
- **Right fix version.** For advisories with one fix per release line, `fix` targets yours (Django 5.1.2 → 5.1.4, not 4.2.17).
- **CI guard finds real leaks.** Scans every committed text file, with rules for Stripe, OpenAI, Anthropic, Slack, Google, private keys, database URLs and `SECRET_KEY` settings; flags committed `.env` files; checks workflows for `pull_request_target` pwn requests, script injection and `write-all`. Line numbers, redacted previews, and `# pydoctor: ignore`. See [CI/CD scanner](/scanners#ci-cd).
- **A score that moves.** A package's advisories count once, categories have diminishing returns, and any critical issue keeps the score at 69 or below. Expect different, usually higher, scores.
- **JSON.** Includes `health`; `scan-security --json` reports advisory IDs (it reported `SEC_VULNERABILITY` for every entry), aliases, fixed version and CVSS score.
- **Smaller fixes.** Database drivers, password hashers and cache clients selected by Django settings count as used; advisories are fetched in parallel; `--no-cache` bypasses the cache instead of deleting it; `github <repo>` and `docker` describe what they actually do.

Upgrade with `pip install --upgrade pydoctor-cli`.

## 2.1.0

- **`fix` reports what really happened.** Upgrades are verified against the installed version. When a pin in `pyproject.toml` blocks an upgrade, `fix` shows a warning and the blocking constraint instead of reporting success. Previously, `uv add --upgrade pkg` could exit successfully without changing anything while `fix` printed "fixed".
- **One prompt per package.** Vulnerable packages are offered once, with the number of advisories, and upgraded to the lowest version that fixes all of them. Uses `pkg>=X` so uv, Poetry, and PDM rewrite blocking pins.
- **No accidental removals.** `pydoctor fix <package>` no longer enables unused-package removal. Removal requires `--remove`.
- **Fewer false "unused" reports.** Packages imported under a different name, loaded from strings such as Django settings, or started from a Procfile, Dockerfile, or similar file are now recognised. Findings are labelled "Possibly unused dependency".

## 2.0.1

- **Security scans fail closed.** When the OSV database cannot be reached, `scan-security`, `diagnose`, and `check` now report `SEC_SCAN_INCOMPLETE` (error, exit code 1) and name the unchecked packages. Previously a network failure produced "No known vulnerabilities" and a perfect score.
- **Aliased advisories are counted once.** An advisory published under several IDs (for example GHSA and PYSEC) is now reported and scored once. Previously each copy deducted points separately, so one critical vulnerability could cost 50 points instead of 25.

Upgrade with `pip install --upgrade pydoctor-cli`.

## 2.0.0

Initial documented release of pydoctor-cli. This entry records the baseline feature set; no prior version source is available for comparison.

- CLI built on Typer with commands `diagnose`, `check`, `fix`, `scan-security`, `scan-unused`, `scan-deps`, `check-env`, `docker`, `github`, and `version`
- Six concurrent scanners: environment, dependencies, outdated packages, security (OSV), unused packages, and CI/CD
- Automated fix workflow with support for pip, Poetry, uv, and pdm
- Rich terminal output and JSON output (`--json`)
- File-backed response cache at `~/.pydoctor/cache.json` with configurable TTL
- Project configuration via `[tool.pydoctor]` in `pyproject.toml`
- Requires Python 3.10 or later
