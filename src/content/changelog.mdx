## 2.2.0

- **Explicit interpreter selection.** All scan commands accept `--python` to specify the project's Python interpreter. The `PYDOCTOR_PYTHON` environment variable provides the same control for CI and scripted use. Auto-detection now describes where it found the interpreter (shown in the terminal report).
- **Expanded secret scanning.** The CI scanner now checks all committed files (not just `.py`) against 12 provider-specific rules (AWS, GitHub, PyPI, Stripe, Anthropic, OpenAI, Slack, Google, private keys, database URLs, framework secret keys) plus a generic entropy-based rule. Low-confidence findings are reported at error severity; high-confidence at critical. Findings include file paths and line numbers. Add `# pydoctor: ignore` on a line to suppress it. `.env` files tracked by git or missing from `.gitignore` are flagged.
- **New workflow checks.** The CI scanner now detects script injection (untrusted GitHub context in `run:` blocks), `permissions: write-all`, and `pull_request_target` workflows that check out PR code. Unpinned action detection is expanded to cover `dev`, `develop`, `head`, and `trunk` branches. Cleartext-secret detection now only flags values that look like real credentials.
- **CVSS v3 scoring.** Vulnerability severity is computed from the advisory's CVSS v3 vector string when available, replacing the previous heuristic. The CVSS base score is included in terminal and JSON output. The `MODERATE` severity label (used by GitHub advisories) is now recognised.
- **Version-aware fix targets.** Vulnerability recommendations now show the fix version for the installed release series, so upgrading within a major line is straightforward.
- **Health score improvements.** Each category has a cap on total deductions with diminishing returns for additional issues. Security vulnerabilities are grouped per package so one upgrade resolves all advisories for that package. Any critical-severity issue caps the score at 69, preventing a Good or Excellent verdict. A new Incomplete verdict appears when part of the scan could not run.
- **pip-free environment support.** The dependency scanner inspects distribution metadata directly when pip is not available, and the outdated-packages scanner falls back to `uv pip list --outdated`. The environment scanner treats pip absence in uv-managed environments as informational rather than an error.
- **`--no-cache` behavior change.** The flag now bypasses cached results for the current run instead of deleting the entire cache file. Fresh data is still written back to the cache.
- **Withdrawn advisory filtering.** OSV advisories that have been withdrawn are no longer reported.
- **Unused-package detection.** Django database backends, URL schemes, hashers, and cache backends are now mapped to their driver packages, reducing false positives.
- **Docker command.** Relabelled from beta to preview, with a clarified scope description.
- **Non-interactive prompt.** The virtual-environment confirmation prompt in `diagnose` is skipped automatically when stdin is not a terminal.

## 2.1.0

- **`fix` reports what really happened.** Upgrades are verified against the installed version. When a pin in `pyproject.toml` blocks an upgrade, `fix` shows a warning and the blocking constraint instead of reporting success. Previously, `uv add --upgrade pkg` could exit successfully without changing anything while `fix` printed "fixed".
- **One prompt per package.** Vulnerable packages are offered once, with the number of advisories, and upgraded to the lowest version that fixes all of them. Uses `pkg>=X` so uv, Poetry, and PDM rewrite blocking pins.
- **No accidental removals.** `pydoctor fix <package>` no longer enables unused-package removal. Removal requires `--remove`.
- **Fewer false "unused" reports.** Packages imported under a different name, loaded from strings such as Django settings, or started from a Procfile, Dockerfile, or similar file are now recognised. Findings are labelled "Possibly unused dependency".

## 2.0.1

- **Security scans fail closed.** When the OSV database cannot be reached, `scan-security`, `diagnose`, and `check` now report `SEC_SCAN_INCOMPLETE` (error, exit code 1) and name the unchecked packages. Previously a network failure produced "No known vulnerabilities" and a perfect score.
- **Aliased advisories are counted once.** An advisory published under several IDs (for example GHSA and PYSEC) is now reported and scored once. Previously each copy deducted points separately, so one critical vulnerability could cost 50 points instead of 25.

Upgrade with `pip install --upgrade pydoctor-cli`.

## 2.0.0

Initial documented release of pydoctor-cli. This entry records the baseline feature set; no prior version source is available for comparison.

- CLI built on Typer with commands `diagnose`, `check`, `fix`, `scan-security`, `scan-unused`, `scan-deps`, `check-env`, `docker`, `github`, and `version`
- Six concurrent scanners: environment, dependencies, outdated packages, security (OSV), unused packages, and CI/CD
- Automated fix workflow with support for pip, Poetry, uv, and pdm
- Rich terminal output and JSON output (`--json`)
- File-backed response cache at `~/.pydoctor/cache.json` with configurable TTL
- Project configuration via `[tool.pydoctor]` in `pyproject.toml`
- Requires Python 3.10 or later
