## Global options

These options apply to the top-level `pydoctor` invocation, before any command name.

| Flag | Description |
|---|---|
| `--version` | Print the version and exit. |

Running `pydoctor` with no arguments prints help.

## Core commands

### `diagnose`

Run a full diagnosis of the project. All registered scanners execute.

```bash
pydoctor diagnose
```

| Option | Short | Default | Description |
|---|---|---|---|
| `--path` | `-p` | `.` | Project directory to scan. |
| `--python` | | auto-detect | Python interpreter of the project to scan. Also `PYDOCTOR_PYTHON`. See [Scanned environment](/scanners#scanned-environment). |
| `--json` | `-j` | `false` | Output results as JSON. |
| `--verbose` | `-v` | `false` | Show detailed output and timing. |
| `--no-cache` | | `false` | Ignore cached advisories for this run (and refresh them). |

When the scanned interpreter isn't a virtual environment, pydoctor prints a warning naming it and, in an interactive terminal, asks whether to continue. It never prompts in JSON mode, in CI, or when input is piped, so non-interactive runs aren't blocked.

**Scanner keys:** all registered scanners (environment, dependencies, outdated, security, unused, ci).

**Exit code:** 1 when any issue has ERROR or CRITICAL severity (including `ENV_PACKAGES_UNAVAILABLE` when the environment can't be read), or when the calculated health score falls below the `min_health_score` threshold set in `[tool.pydoctor]`. Otherwise 0.

### `check`

Security and health check with an optional CI/CD guard mode.

```bash
pydoctor check --ci
```

| Option | Short | Default | Description |
|---|---|---|---|
| `--path` | `-p` | `.` | Project directory to scan. |
| `--python` | | auto-detect | Python interpreter of the project to scan. Also `PYDOCTOR_PYTHON`. See [Scanned environment](/scanners#scanned-environment). |
| `--ci` | | `false` | Restrict the scan to only the `ci` scanner. |
| `--json` | `-j` | `false` | Output results as JSON. |
| `--verbose` | `-v` | `false` | Show detailed output and timing. |

**Scanner keys:** without `--ci`, all registered scanners run (including `ci`). With `--ci`, only the `ci` scanner runs.

**Exit code:** same rules as `diagnose`.

### `fix`

Scan the project and attempt automated fixes: upgrade vulnerable or outdated packages, resolve dependency conflicts, remove unused packages, and create a virtual environment if missing. Dispatches to the appropriate package manager (pip, Poetry, uv, or PDM) based on project configuration.

```bash
pydoctor fix
```

| Option | Short | Default | Description |
|---|---|---|---|
| `--path` | `-p` | `.` | Project directory to scan. |
| `--python` | | auto-detect | Python interpreter of the project to scan. Also `PYDOCTOR_PYTHON`. See [Scanned environment](/scanners#scanned-environment). |
| `--safe` / `--no-safe` | | `--safe` | When safe, confirm each action interactively. |
| `--upgrade` / `--no-upgrade` | | `--upgrade` | Upgrade outdated packages. |
| `--remove` / `--no-remove` | | `--no-remove` | Remove unused packages. |

A positional `packages` argument optionally limits fixes to the named packages. Unused-package removal runs only when `--remove` is passed.

Each upgrade is verified against the installed version afterwards. An upgrade that leaves the version unchanged is reported as a warning, not a fix. See [Fixing issues](/guides/fixing-issues#how-upgrades-are-applied-and-verified).

**Scanner keys:** all registered scanners (used internally to produce the report that drives fixes).

**Exit code:** 0 on completion.

## Security and CI/CD commands

### `scan-security`

Run only the OSV vulnerability scanner against installed packages.

```bash
pydoctor scan-security
```

| Option | Short | Default | Description |
|---|---|---|---|
| `--path` | `-p` | `.` | Project directory to scan. |
| `--python` | | auto-detect | Python interpreter of the project to scan. Also `PYDOCTOR_PYTHON`. See [Scanned environment](/scanners#scanned-environment). |
| `--json` | `-j` | `false` | Output results as JSON. |
| `--verbose` | `-v` | `false` | Show detailed output and timing. |

**Scanner keys:** `security`.

**Exit code:** 1 if any vulnerability has ERROR or CRITICAL severity, if the OSV database could not be reached (`SEC_SCAN_INCOMPLETE`), or when the health score falls below the `min_health_score` threshold. Otherwise 0.

### `docker`

Check for a Dockerfile and whether it uses a Python base image. This command does not run any scanners. It is a preview feature that only checks the Dockerfile; it does not inspect images or containers.

```bash
pydoctor docker
```

| Option | Short | Default | Description |
|---|---|---|---|
| `--path` | `-p` | `.` | Project directory to check. |

A positional `image` argument is accepted but currently unused beyond display.

**Scanner keys:** none.

**Exit code:** 0.

### `github`

Run the CI/CD guard on a local git checkout. Checks git repository status when not in JSON mode.

```bash
pydoctor github
```

| Option | Short | Default | Description |
|---|---|---|---|
| `--path` | `-p` | `.` | Project directory to scan. |
| `--python` | | auto-detect | Python interpreter of the project to scan. Also `PYDOCTOR_PYTHON`. See [Scanned environment](/scanners#scanned-environment). |
| `--json` | `-j` | `false` | Output results as JSON. |
| `--verbose` | `-v` | `false` | Show detailed output and timing. |

A positional `repo` argument is accepted but remote repositories aren't supported yet: pydoctor prints a warning and scans `--path`.

**Scanner keys:** only the `ci` scanner (CI mode is always on, which restricts the scan to the `ci` scanner).

**Exit code:** same rules as `diagnose`.

## Utility commands

### `version`

Print the pydoctor version string.

```bash
pydoctor version
```

No options. Exit code 0.

### `cache clear`

Empty the local cache file at `~/.pydoctor/cache.json`.

```bash
pydoctor cache clear
```

No options. Exit code 0.

### `cache purge`

Remove only expired entries from the cache. The TTL defaults to 3600 seconds and can be changed with the `PYDOCTOR_CACHE_TTL` environment variable.

```bash
pydoctor cache purge
```

No options. Exit code 0.

There is no `cache info` subcommand. Only `clear` and `purge` are implemented.

## Cache bypass behavior

The `--no-cache` flag on the `diagnose` command skips reading cached results for the current run. Fresh data is fetched from the OSV API and written back to the cache, so subsequent runs without `--no-cache` use the updated entries. The flag does not delete the cache file; use `cache clear` for that.
